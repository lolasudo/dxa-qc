# Обучение и дообучение моделей

В документе описано, как получить веса с нуля, дообучить модели на новых данных и масштабировать
обучение на большие датасеты. Протокол оценки и результаты описаны в
[backend/README.md](../backend/README.md#оценка-качества).

## Что обучается

| Модель | Файл | Время |
|---|---|---|
| Классификатор области и стороны (HOG + ЛР) | `region_classifier.npz` | секунды, CPU |
| Бэкбоны (замороженные, из timm) | `backbones/*.safetensors` | однократная загрузка, нужна сеть |
| Модели качества (геометрия + эмбеддинги -> логистические головы) | `quality_spine.npz`, `quality_hip.npz` | ~5 мин на RTX 3050 при 20 повторах CV; с кэшем эмбеддингов - секунды на повтор |

Бэкбоны не дообучаются: на ~250 снимках fine-tuning проигрывал замороженным признакам
(см. таблицу отвергнутых вариантов в backend/README). Обучаются линейные головы, их пороги и
калибровка.

## Быстрый путь: в контейнере

Используется тот же образ, что в сервисе, с теми же версиями библиотек.

```bash
scripts/build.sh

# датасет организатора: Датасет/Исследования + Датасет/разметка.xlsx
scripts/train.sh --data Датасет --output backend/weights.new

# собственный датасет: каталог с DICOM + манифест
scripts/train.sh --data /data/dxa --manifest /data/dxa/manifest.csv --output backend/weights.new

# после проверки метрик (backend/weights.new/quality_metrics.json)
rm -rf backend/weights && mv backend/weights.new backend/weights && scripts/run.sh
```

Опции: `--config <yaml>` задаёт свой конфиг обучения, `--reps N` - число повторов CV (для быстрой
пробы подойдёт 1), `--download-backbones` скачивает бэкбоны из конфига (нужна сеть), `--gpu`.
`scripts/train.sh` по очереди строит манифест, обучает классификатор области и модели качества,
а метрики записывает в `quality_metrics.json`. Рабочие веса `backend/weights` скрипт не трогает.

## Манифест обучения

Один CSV на весь датасет, одна строка на снимок, кодировка UTF-8. Такой формат подходит для
данных любого объёма и происхождения. Реализация и валидация - `backend/src/dxa_qc/data/manifest.py`.

```csv
path,study_id,region,side,overall,positioning,spine_axis,foreign_objects,hip_roi,comment
s001/img1.dcm,s001,spine,,1,0,1,0,,
s001/img2.dcm,s001,hip,left,0,0,,,0,
s002/img1.dcm,s002,,,,,,,,unlabeled - region detected by the classifier
```

| Колонка | Правило |
|---|---|
| `path` | путь относительно корня изображений (`--images-root`, по умолчанию - каталог манифеста). Абсолютные пути и `..` запрещены |
| `study_id` | группа CV: снимки одного исследования (пациента) никогда не попадают в разные фолды. **Обязательна** |
| `region` | `spine` / `hip` / пусто (тогда область определяет классификатор) |
| `side` | для бедра `left` / `right` / пусто (определяется); для позвоночника - пусто |
| `overall` | вердикт эксперта: 1 - есть нарушение, 0 - качественное, пусто - снимок без разметки |
| `positioning`, `spine_axis`, `foreign_objects`, `hip_roi` | 1 - нарушено, 0 - нет. Обязательны при заполненном `overall` для критериев своей области и должны быть пустыми для чужих (`hip_roi` у позвоночника, `spine_axis`/`foreign_objects` у бедра) |
| `comment` | произвольный текст |

Размеченные строки требуют явной области. Любая ошибка в манифесте останавливает обучение с номером
строки: дубликат пути, выход за корень, неизвестное значение, пропущенный критерий. Побайтовые
дубли снимков внутри исследования учитываются один раз.

Манифест из формата организатора (`разметка.xlsx` + проверенная таблица областей):

```bash
cd backend
python -m dxa_qc.training.make_manifest --studies ../Датасет/Исследования \
    --labels ../Датасет/разметка.xlsx --annotations data/region_annotations.csv \
    --output ../Датасет/manifest.csv
```

## Дообучение на новых данных

1. Сложите новые снимки к старым (или в отдельный каталог под общим корнем) и допишите строки в
   манифест. `study_id` должен быть уникален для исследования **во всём** манифесте.
2. Запустите `scripts/train.sh` с объединённым манифестом. Эмбеддинги старых снимков берутся из
   кэша, пересчитываются только новые.
3. Сравните `quality_metrics.json` с текущим: ROC-AUC и F1 с 95% ДИ по каждой области и каждому
   нарушению, `ALL_REGIONS` - обе области вместе. Меняйте веса только при устойчивом улучшении, а не
   при сдвиге внутри ДИ. `error_analysis` каждой области показывает качество по клиническим
   пометкам из колонки `comment` (сколиоз, эндопротез, перелом, переходный позвонок) и список
   снимков, на которых модель ошибается в большинстве повторов CV: их стоит показать эксперту.
4. Замените `backend/weights` и перезапустите сервис. Вместе с моделью сохраняются хеш манифеста
   (`dataset_sha256`), конфиг голов и sha256 бэкбонов - это позволяет воспроизвести результат.

Источник исправленных меток - `results_reviewed.csv` из архива результатов: там решение
специалиста (`review_quality_class`, `review_violation_type`) стоит рядом с решением модели и путём
к снимку. Проверенные строки переносятся в манифест как новые размеченные снимки.

Классификатор области обучается на всех строках манифеста с явной областью (и стороной для
бедра), размеченных и неразмеченных. Разметка области дешёвая, поэтому на больших датасетах её
обычно гораздо больше, чем экспертной оценки качества.

## Настройки: `backend/configs/training.yaml`

| Ключ | Смысл | Большой датасет |
|---|---|---|
| `cv.n_splits`, `cv.repetitions` | групповые фолды и число повторов CV | 5 фолдов; 3-5 повторов вместо 20 (дисперсия меньше) |
| `cv.bootstrap` | ресэмплы для 95% ДИ | 1000 |
| `heads.geometry_c`, `heads.embedding_c` | сила L2: одно число - фиксировано; список - автоподбор по AUC на вложенной групповой CV внутри каждого обучающего фолда (без утечки) | задайте сетку, например `[0.001, 0.01, 0.1, 1]` |
| `heads.inner_splits` | фолды вложенной CV | 3 |
| `embedding.batch_size`, `embedding.device` | пакет инференса бэкбонов, `auto` / `cpu` / `cuda` | 64-256 на H200 |
| `embedding.cache_dir` | кэш эмбеддингов (`.npy` по хешу пикселей и спецификации бэкбона) | оставьте включённым |
| `regions.<область>.backbones` | любые модели timm: `key`, `timm`, `input_size`, `crop` | можно добавить более крупные бэкбоны |

Неизвестные ключи и значения вне диапазона считаются ошибкой при загрузке конфига. Порядок
смены бэкбонов:

```bash
# 1) добавить бэкбон в training.yaml, например
#    - {key: convnextb_full, timm: convnext_base.fb_in22k_ft_in1k, input_size: 224}
# 2) скачать веса (нужна сеть) и обучить
scripts/train.sh --data /data/dxa --manifest /data/dxa/manifest.csv --config my_training.yaml \
    --download-backbones --output backend/weights.new
```

Спецификации бэкбонов и их sha256 записываются в файл модели. Сервис загружает ровно те бэкбоны, на
которых обучены головы, и отказывается работать при несовпадении хеша.

## Масштабирование

- **Память.** Снимки читаются потоково, пакетами `embedding.batch_size`. В памяти остаются только
  векторы эмбеддингов (float32: 1.5 КБ у DINOv2-S, 3 КБ у ConvNeXt-S, 6 КБ у EfficientNet-B3),
  то есть ~5-8 КБ на снимок при двух бэкбонах. 100 тыс. снимков занимают меньше 1 ГБ.
- **Время.** Основные затраты - инференс бэкбонов, один раз на снимок. Повторные запуски с другими
  головами, C или CV используют кэш. Логистические головы на 10⁵ строк обучаются за секунды.
- **Устойчивость.** Нечитаемые файлы пропускаются с предупреждением и подсчётом в логе. Цели с
  одним классом в данных останавливают обучение: такую цель обучить нельзя.
- **Честность метрик.** Группировка по `study_id` обязательна: без неё снимки одного пациента
  попадут и в обучение, и в проверку, и метрики окажутся завышенными.

## Локально, без Docker

```bash
cd backend
python -m dxa_qc.training.backbones --weights-dir weights/backbones [--config configs/training.yaml]
python -m dxa_qc.training.region  --manifest ../Датасет/manifest.csv --output weights/region_classifier.npz
python -m dxa_qc.training.quality --manifest ../Датасет/manifest.csv --weights-dir weights [--config ...] [--reps N]
```

Старый вызов `--studies/--labels/--annotations` по-прежнему работает: манифест строится
автоматически.
