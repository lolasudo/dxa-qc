# Демонстрационный сценарий (~10 минут)

Порядок показа: клиническая логика, архитектура, работа на новых данных, метрики, ограничения.

## Подготовка (до показа)

```bash
npm start                      # сервис на http://localhost:7077, дождаться «Сервис готов»
scripts/check_offline.sh       # доказательство автономности - вывод показать на шаге 6
```

Приготовьте архив `Датасет/Для теста.zip`: 3 снимка, которые организатор выдал для проверки
формата. Эти снимки **не входили в обучение**. Откройте светлую тему, в тёмной - отдельный слайд.

## 1. Задача и клиническая логика (1 мин)

Некачественная денситометрия (посторонние предметы, наклон, неверная укладка, неверная область
интереса) искажает МПКТ, и повторное исследование - это новая доза облучения. Сервис проверяет
снимок сразу после исследования, пока пациент ещё в кабинете.

Таксономия: для позвоночника - укладка, ось, посторонние предметы; для бедра - укладка и область
интереса. У одного снимка может быть несколько нарушений (мультилейбл). Любое нарушение означает
`quality_class = 1`.

## 2. Пакетная обработка на новых данных (3 мин)

1. Плашка «Пакетная проверка» -> перетащить `Для теста.zip` -> ход обработки -> через ~2 с «Готово».
2. Сводка: 3 снимка, 2 с нарушениями, 1 качественный, 0 не обработано.
3. Таблица -> открыть `CR000000_ПОП.dcm` (позвоночник): **посторонние предметы**, вероятность ~0.91.
   Включить разметку: подсвечены найденные предметы в мягких тканях. Прочитать заключение.
4. Открыть `CR000000_ППОБ.dcm` (правое бедро): **некорректная укладка**, ~0.59, то есть пограничный
   случай. Показать ось диафиза на разметке и измеренный угол. Пояснить, что укладка бедра - самый
   трудный критерий, где сами эксперты расходятся.
5. Открыть `CR000001_ЛПОБ.dcm` (левое бедро): **качественное**, ~0.32.
6. «Скачать отчёт» -> показать `results.xlsx`, папки `visualization/` и `dicom/`.

Имена файлов модель не использует: область и сторона определяются по пикселям. Если спросят, можно
переименовать файл и загрузить заново - результат не изменится.

## 3. Один снимок (1 мин)

Плашка «Один снимок» -> загрузить любой DICOM -> результат через секунду. Это сценарий для кабинета.

Показать предложение по коррекции и нажать «Исправить»: отметить итог, добавить комментарий,
сохранить. Появляется отметка «Исправлено специалистом», кнопка «DICOM SR» отдаёт проверенный
(VERIFIED) отчёт.

## 4. Устойчивость (1 мин)

Загрузить архив, в котором вместе с DICOM лежат `readme.txt` и битый `broken.dcm`. Пакет
обрабатывается полностью: `.txt` пропускается, `broken.dcm` получает статус «не обработан» с
причиной «not a valid DICOM file», необработанных исключений нет.

## 5. Архитектура и метрики (3 мин)

- Конвейер: DICOM -> проверка -> изотропная сетка 1 мм -> область и сторона (HOG + ЛР, 100%) ->
  геометрия в мм + 2 замороженных бэкбона на регион -> логистические головы -> решения на сырых
  скорах, Platt только для вероятности.
- Оценка: 20 повторов групповой 5-fold CV, группа = исследование, пороги подбираются только на
  обучающих фолдах, bootstrap 95% ДИ по исследованиям.
- Результаты: позвоночник ROC-AUC 0.86 [0.77-0.94], F1 0.71; бедро ROC-AUC 0.73 [0.61-0.83],
  F1 0.53; обе области вместе ROC-AUC 0.78 [0.71-0.84], F1 0.61; область - 100%.
- Анализ ошибок: на сколиозе специфичность по позвоночнику 0.71 против 0.79 - кривизна похожа на
  невыровненную ось.
- Что пробовали и отвергли: fine-tuning CNN, стекинг, крупные бэкбоны - таблица в backend/README.
- Потолок данных: 6-7 положительных у редких нарушений, шум разметки, расхождение «угла» и решений
  экспертов -> план доразметки.

## 6. Внедрение (1 мин)

- `scripts/check_offline.sh`: сервис и пакетная обработка работают в контейнере без сети.
- Скорость ~0.5 с на снимок на CPU и ~0.07 с на GPU при лимите 3 минуты; пик памяти < 1 ГБ.
- Поставка в закрытый контур: образы и веса одним архивом с контрольными суммами.
- Безопасность: non-root, read-only, лимиты против DoS, CI со сканированием уязвимостей и SBOM.
- Дообучение на данных клиники: манифест CSV + `scripts/train.sh`, с кэшем эмбеддингов.

Модель видела эти снимки при обучении, поэтому метрики на них не показательны. Они нужны только
для иллюстрации визуализации редких нарушений.

| Некорректная область интереса (бедро) | `2.25.13069823278093578548407087310307113784/series_003_2_CR/...` |
| Некорректная укладка (позвоночник) | `2.25.52982400970721161435951723390541696819/series_001_2_CR/...` |

Кейс с наклоном оси подберите по `results.xlsx` полного прогона (`violation_type` =
`Не выравнена ось позвоночника`).
